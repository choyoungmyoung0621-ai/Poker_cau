# FELT | 홀덤 ♠ + 블랙잭 ♥ 실시간 멀티플레이

친구들과 **한 개의 사이트에서 텍사스 홀덤과 블랙잭을 선택**해 즐기는 무료 웹 게임 프로젝트입니다. **실제 돈·현금화·결제 기능은 없으며, 게임 내 가상 칩만 사용합니다.**

- **GitHub**: 소스코드 저장 및 자동 배포 연결
- **Cloudflare Workers + Durable Objects**: 무료 사용 한도 내에서 정적 화면과 실시간 게임 서버 동시 운영
- **실시간 통신**: WebSocket (서버 권한 중심, hibernation 지원)
- **홀덤**: 2~8명, 사이드 팟, 25초 턴, 암호학적 셔플 커밋
- **블랙잭**: 1~8명, 공용 딜러, 히트·스탠드·더블다운·스플릿, 공정한 서버 판정
- **가입 불필요**: 닉네임과 6자리 방 코드로 입장, 새로고침 시 재접속
- **서로 다른 방과 서로 다른 게임 종류는 완전히 분리**됩니다. 홀덤 방 코드는 블랙잭에서 사용할 수 없습니다.

## 🎲 플레이 화면

- **홀덤**: 배포 주소의 `/` — 오른쪽 위 `♥ BLACKJACK 해보기` 버튼으로 블랙잭 이동
- **블랙잭**: 배포 주소의 `/blackjack.html` — 상단 `TEXAS HOLD'EM` 메뉴로 홀덤 이동
- 게임마다 **방을 따로 생성**합니다. 초대 링크에는 각 게임 종류의 페이지가 포함됩니다.

## 🚀 가장 간단한 배포 (GitHub → Cloudflare)

**Northflank, Firebase, GitHub Pages는 필요 없습니다.** GitHub는 코드 저장소로 쓰고, Cloudflare에 화면과 게임 서버를 함께 올립니다.

1. [GitHub](https://github.com)에 새 **공개(Public) 저장소**를 만듭니다. 예: `felt-poker`.
2. ZIP 파일의 압축을 풀고 **최상위 파일/폴더를 전부** 업로드합니다. ZIP 자체를 올리는 게 아니라 아래의 파일들이 저장소의 최상위에 있어야 합니다. `Add file → Upload files → Commit changes`.
   - `public/` (홀덤과 블랙잭 화면, CSS/JS)
   - `src/` (홀덤/블랙잭 규칙, 공용 서버)
   - `test/` (자동 테스트)
   - `package.json`, `wrangler.jsonc`, `.gitignore`, `README.md`
3. [Cloudflare](https://dash.cloudflare.com)에 무료 계정으로 가입합니다.
4. **Workers & Pages**에서 GitHub 저장소를 연결하여 **Worker**로 배포하는 옵션을 선택합니다. **Pages 정적 사이트만 만드는 옵션이 아닙니다.** Cloudflare의 메뉴 명칭은 바뀔 수 있습니다.
5. 배포 과정에서 이 저장소의 `wrangler.jsonc` 설정을 사용하고, 필요한 경우 다음 명령을 입력합니다.
   - 빌드/설치: `npm install`
   - 배포: `npx wrangler deploy`
6. Cloudflare가 발급한 `https://<worker-name>.<account>.workers.dev` 주소를 엽니다. 홈 화면에서 홀덤 또는 블랙잭을 선택할 수 있습니다.
7. 닉네임으로 방을 만들고 **초대 링크를 공유**하세요. 친구들이 각자 링크에 접속해 참여합니다.

**중요:** GitHub만으로는 이 프로젝트의 WebSocket 서버가 실행되지 않습니다. Cloudflare 배포 연결은 한 번 필요합니다. 배포 UI가 다른 경우 해당 화면을 캡처해 확인하세요.

## 🃏 블랙잭 규칙

- 6벌의 52장 카드로 구성된 덱(총 312장)을 **매 라운드 암호학적 난수로 셔플**합니다.
- 플레이어는 딜러에게 각각 개별 베팅합니다. 다른 플레이어의 칩을 빼앗는 방식이 아닙니다.
- 시작 칩: 1,000개 / 베팅: **10~200칩, 10칩 단위** / 베팅 0은 관전.
- 방장이 `게임 시작`을 눌렀을 때 접속 중이며 베팅이 유효한 플레이어가 참여합니다(최소 1명).
- 히트: 1장 추가 / 스탠드: 현재 핸드 확정 / 더블다운: 베팅 2배, 카드 1장만 추가.
- 스플릿: 첫 두 장의 **블랙잭 점수가 같은 카드**면 두 손패로 분리. 각 손패마다 기존 베팅만큼 추가 칩이 필요합니다. **최대 4핸드**까지 가능합니다.
- 스플릿한 에이스는 각각 카드 한 장만 추가로 받고 스탠드합니다. 스플릿한 핸드의 21은 내추럴 블랙잭이 아닙니다.
- 딜러는 **소프트 17에서도 스탠드(S17)**하고, 16 이하는 히트합니다.
- **내추럴 블랙잭(처음 두 장이 21)**은 3:2 지급(베팅 20칩이면 수익 30칩). 일반 승리는 1:1 지급. 무승부는 베팅 반환. 패배 시 베팅 손실.
- 딜러의 처음 두 장이 블랙잭이면 즉시 종료합니다(플레이어 블랙잭과는 무승부).
- 보험, 서렌더 기능은 없습니다.
- 행동 제한 시간 25초. 시간 초과 시 자동 스탠드. 라운드 도중 연결이 끊겨도 재접속할 수 있습니다.
- 칩이 10개 미만이면 라운드 후 가상 칩 1,000개를 다시 받을 수 있습니다.
- 상대 플레이어의 핸드는 공개하며, **딜러의 두 번째 카드는 결과 발표 전까지 서버가 숨깁니다.**
- 라운드 시작 전 카드 순서의 SHA-256 해시를 공개하고, 결과 후 원본 덱/nonce/배분 위치를 공개해 덱 변조·카드 중복을 점검합니다. 이는 운영자가 덱을 애초에 임의로 선택하지 않았다는 사실까지 증명하는 것은 아닙니다.

## ♠ 홀덤 규칙

- 2~8명, 시작 칩 1,000개, 스몰 블라인드 10 / 빅 블라인드 20, 25초 턴.
- 체크 / 콜 / 폴드 / 레이즈 / 올인, 족보·무승부·사이드 팟 정산.
- 시간 초과 시 체크 가능하면 체크, 아니면 폴드.
- 다른 플레이어의 개인 카드는 게임이 진행되는 동안 전송하지 않습니다.
- 시작 시 카드 배분의 SHA-256 커밋, 게임 후 셔플 원본 공개·검증.

## 🧰 로컬 실행과 테스트

Node.js 20 이상 설치 후 프로젝트 폴더에서 실행:

```bash
npm install
npm run dev
```

터미널에 나오는 로컬 주소(일반적으로 `http://localhost:8787`)에서 홀덤과 `/blackjack.html`을 확인할 수 있습니다.

```bash
npm test
npm run check
```

- 기존 홀덤 규칙 테스트 14개(400핸드 랜덤 시뮬레이션 포함)
- 블랙잭 규칙 테스트 14개(320라운드 랜덤 시뮬레이션 포함)
- 총 **28개 자동화 테스트**가 통과하도록 작성했습니다.

## 기술 구조

```text
친구들 브라우저 (PC/모바일)
    ↕ HTTPS / WebSocket
Cloudflare Worker ── public/index.html + public/blackjack.html 외 정적 파일
    ↕
Durable Object (방 코드별로 고유 인스턴스)
    ├─ mode: poker 또는 blackjack (생성 시 고정)
    ├─ 서버 권한 베팅·패 섞기·턴 및 결과 판정
    ├─ 클라이언트별 게임 상태 전송
    ├─ WebSocket 재접속 및 중복 요청 방지
    ├─ 시간 제한 알람 및 영속 저장
    └─ 라운드 종료 후 셔플 검증 기록
```

`wrangler.jsonc`의 Durable Object 클래스 이름은 `PokerRoom`으로 유지됩니다. **기존 홀덤 방 및 데이터와 호환성을 유지하기 위한 이름**이며, 해당 클래스가 두 게임 모두를 처리합니다. 기존 프로젝트를 업데이트하는 경우 별도로 Durable Object 마이그레이션을 추가할 필요가 없습니다.

## 무료·지연 관련 주의점

Cloudflare에는 무료 한도와 요청/스토리지/실행 시간 제한이 있습니다. 사용량이 한도를 초과하면 연결이나 배포가 제한될 수 있으니 [Durable Objects 요금/한도](https://developers.cloudflare.com/durable-objects/platform/pricing/)와 [Workers 한도](https://developers.cloudflare.com/workers/platform/limits/)를 확인하세요.

매 판마다 서버가 카드를 셔플하고 결과를 판정하며, 웹브라우저는 게임 화면만 표시합니다. 빠르고 공정한 소규모 멀티플레이를 목표로 하지만 **렉 0ms, 무중단 운영을 보장하지는 않습니다**.

**검증 범위:** Node.js 테스트와 구문 검증을 수행했습니다. 실제 Cloudflare 배포, 실인터넷 다중 접속 및 지연시간 측정은 아직 하지 않았습니다. 서버 운영자가 게임 코드를 바꾸는 수준의 공격까지 방지하는 감사 시스템은 아닙니다.
